# 事前準備ガイド（相談予約システム）

このガイドは、**本人がブラウザで行う設定**をまとめたものです。ログインや認証を伴うので、AIには代行できません。
所要時間の目安は **30〜60分**。控えるものは、最後の「控えメモ」欄に書き込んでください。

> ⚠️ **最初に読んでください：エルメを止めないための注意**
>
> LINE公式アカウントには、エルメが動くための設定が入っています。次の2つは**絶対に触らないでください**。
> - Messaging API設定の **Webhook URL**（エルメのURLが入っています。書き換えるとエルメが止まります）
> - チャネルアクセストークンの **「再発行」ボタン**（既存のトークンが無効になり、エルメが止まる可能性があります）
>
> このガイドの手順は、どちらにも触れずに進められるように組んであります。

---

## STEP 1｜Google側の準備（10分）

### 1-1. 申し込み台帳のスプレッドシートを作る
1. https://sheets.new を開いて、新しいスプレッドシートを作る
2. 名前を「相談予約 台帳」などにする（中身は空でOK。見出しは自動で作られます）
3. URLの `/d/` と `/edit` の間の文字列を控える → **【SHEET_ID】**
   例：`https://docs.google.com/spreadsheets/d/1AbCdEfG.../edit` → `1AbCdEfG...`

### 1-2. 予約を入れるカレンダーを決める
- 普段使っているメインのカレンダーに入れるなら **【CALENDAR_ID】= `primary`**
- 相談専用のカレンダーを分けたい場合（**おすすめ**。他システムとカレンダー連携している人は必須）：
  1. `https://calendar.google.com/calendar/u/0/r/settings/createcalendar` を開く
  2. 「名前」に `相談予約` と入れて「**カレンダーを作成**」（タイムゾーンは日本標準時のまま）
  3. 左の「**マイカレンダーの設定**」に出てきたそのカレンダー名をクリック
  4. 下の方の見出し「**カレンダーの統合**」にある**カレンダー ID**（`xxxx@group.calendar.google.com`）を控える → **【CALENDAR_ID】**
- 専用カレンダーでも Google Meet のURLは自動発行される（2026-09-08 実測）

> ⚠️ **複数のGoogleアカウントを使っている人へ**：この後の作業は全部**同じアカウント**で行ってください。
> 台帳を作ったアカウントとGASを作るアカウントがずれると、`selfCheck` でスプレッドシートNGになります。

## STEP 2｜LINE側の準備（20〜30分）

LINE Developers コンソール https://developers.line.biz/console/ にログインします（LINE公式アカウントと同じLINEアカウントで）。

> 未ログインだと **「LINEヤフーBusiness ID」** のログイン画面に飛びます（2026-09-08 実測）。
> 選択肢は上から **LINEアカウント / メールアドレス / Yahoo! JAPAN ID / パスキーでログイン** の4つ。
> ふだんLINE公式アカウントを管理しているのと同じ入口を選んでください。

### 2-1. プロバイダーを開く
- 左の一覧から、**エルメと接続しているLINE公式アカウントが入っているプロバイダー**を開く
- 中に「Messaging API」のチャネルがあるはずです（これがエルメと繋がっているもの）

### 2-2. LINEログインチャネルを新しく作る（LIFF用）
LIFF（LINEの中で開く画面）は、Messaging APIとは**別のチャネル**に登録します。なのでエルメの設定には触れません。
（Messaging APIチャネルのLIFFタブには「**Messaging APIチャネルには、LIFFアプリを追加できません**」と明記されています）

> 💡 **なぜエルメと同じプロバイダーに作るのか**（2026-09-08 実測）
> LINEの userId は**プロバイダー単位で共通**です。エルメと同じプロバイダーの中に作れば、
> LIFFで取得した userId と、Messaging APIチャネルから送るときの userId が一致します。
> 別のプロバイダーに作ると userId が変わり、**確認メッセージの送信が400エラーで失敗します**。
> （同じプロバイダー内の2チャネルで userId が完全一致することを実機で確認済み）

1. プロバイダーの画面で「**新規チャネル作成**」を押す
   → チャネルの種類を選ぶダイアログが出る。**LINEログイン / Messaging API / ブロックチェーンサービス / LINEミニアプリ** の4つから
   「**LINEログイン**」を選ぶ
2. 入力する（⚠️ 以下の3つは以前は無かった項目です）
   - **サービスを提供する地域**：`日本`
   - **会社・事業者の所在国・地域**：`日本`（**未設定だとエラーで先に進めません**）
   - チャネル名：`相談予約フォーム`（何でもOK・20文字以内）
   - チャネル説明：`無料相談の予約画面`
   - アプリタイプ：**ウェブアプリ** にチェック
   - **2要素認証の必須化**：**ONのまま**でOK（既定でON）。PCブラウザから予約する人にだけ2段階認証が要求されます。
     友だちがLINEアプリの中から開く分には影響しません
   - メールアドレス：自分のもの（自動で入っていることが多い）
   - プライバシーポリシーURL / サービス利用規約URL：任意（空欄でOK）
3. 一番下の「**LINE開発者契約 に同意します。**」にチェック →「**作成**」

> ⚠️ 作成直後のチャネルは **「開発中」** という状態です。この状態では、**チャネルの管理権限を持つ人しか予約画面を開けません**。
> 自分でテストする分には問題ありませんが、**お客様に配る前に「公開」に切り替えてください**
> （チャネル名の横の「開発中」バッジから切り替えます）。

### 2-3. LIFFアプリを追加する
1. 作ったLINEログインチャネルを開き、上のタブ「**LIFF**」→「**追加**」

   > 画面に「新規にLIFFアプリを作成する場合はLINEミニアプリでの作成を推奨しています」という案内が大きく出ますが、
   > **LIFFのままで問題ありません**（同じ案内の※2に「今後作成されるLIFFアプリも引き続きご利用いただけます」と書かれています）。

2. 入力する

   | 項目 | 値 |
   |---|---|
   | LIFFアプリ名 | `相談予約` |
   | サイズ | **Full** |
   | エンドポイントURL | いったん `https://example.com` と入れる（STEP 4 で本物に差し替えます） |
   | Scope | **profile** だけでOK（`openid` は不要。このキットは `liff.getProfile()` しか使いません。お客様に求める同意は少ないほどよいので、あえて付けません） |
   | **友だち追加オプション** | **On (Aggressive)** ← これで予約画面を開いた人が友だち追加されます。※ 以前は「ボットリンク機能」という名前でした |
   | Scan QR / モジュールモード | オフのままでOK |

3. 「追加」を押すと **LIFF ID**（例：`1234567890-AbCdEfGh`）が表示される → **【LIFF_ID】** として控える
   - 一覧に出た行の**右端の「＞」**を押すと、その LIFF の詳細（エンドポイントURLの編集など）が開きます

### 2-4. リンクするLINE公式アカウントを設定する（⚠️ 自動では設定されません）
LIFFの「友だち追加オプション」を On にしても、**リンク先の公式アカウントは自動では紐づきません**。明示的に設定します。

1. LINEログインチャネルの「**チャネル基本設定**」タブを開く
2. 下の方の「**友だち追加オプション**」→「**リンクされたLINE公式アカウント**」を見る。初期値は `–`（未設定）
3. 「**編集**」→ プルダウンから **エルメと繋がっているMessaging APIチャネル**（`@から始まるID/チャネル名` の形で出ます）を選ぶ →「**更新**」
4. 表示が `–` から選んだアカウント名に変わっていれば完了

選ぶだけなので、そのMessaging APIチャネル側の設定（Webhookなど）は一切変わりません。

### 2-5. Messaging APIのチャネルアクセストークンを用意する
予約確認メッセージをLINEに送るために必要です。**ここだけ慎重に**。

1. プロバイダーの画面で、**Messaging APIチャネル**（エルメと繋がっている方）を開く
2. 上のタブ「**Messaging API設定**」を開く
3. 一番下の「**チャネルアクセストークン（長期）**」を見る

   **A. 「発行」ボタンだけがあり、トークンが表示されていない場合**
   → まだ発行されていない状態です。「発行」を押して、表示されたトークンを **【LINE_CHANNEL_ACCESS_TOKEN】** として控えてください。エルメには影響しません。
   （エルメ運用中のアカウントで実測したところ、この **A** の状態でした。エルメは「チャネルID＋チャネルシークレット」で繋がっていて長期トークンを使っていないため、発行しても配信は止まりませんでした）

   **B. すでにトークンが表示されている場合**
   → 表示されているものをそのまま控えてください。**「再発行」は押さないでください。**

   **C. トークンが表示されておらず、「再発行」ボタンになっている場合**
   → 過去に発行済みで、値が見えない状態です。**ここで止まって担当者に相談してください。** 再発行するとエルメが止まる可能性があるため、別の方法（v2.1トークンの発行）で対応します。

> 💡 エルメとの接続で「チャネルID」と「チャネルシークレット」を入力した方式なら、エルメはこの長期トークンを使っていない可能性が高いです。ただし念のため、STEP 6 のテストでエルメの配信も一緒に確認してください。

### 2-6. 通知の宛先（任意）
予約が入ったときに**自分のLINEにも通知**したい場合は、自分の LINE userId を控えます（`U` から始まる33文字）。
- Messaging APIチャネルの「チャネル基本設定」タブ → 一番下の「**あなたのユーザーID**」→ **【ADMIN_LINE_USER_ID】**

## STEP 3｜GAS（裏側の処理）を置く（15分）

1. https://script.google.com を開き、「**新しいプロジェクト**」
2. 左上の「無題のプロジェクト」を「相談予約フォーム」に変更
3. **設定（歯車）** → 「**appsscript.json マニフェスト ファイルをエディタで表示する**」にチェック
4. エディタに戻り、`コード.gs` の中身を全部消して、キットの `gas/Code.gs` の中身を貼り付ける
5. `appsscript.json` を開いて、中身を全部消して、キットの `gas/appsscript.json` の中身を貼り付ける
6. 左の「**サービス**」の「＋」→ **Google Calendar API** を選んで「追加」（Google Meet のURLを自動発行するために必要）
7. **設定（歯車）** → 「**スクリプト プロパティ**」→「プロパティを追加」で次を入れる

   | プロパティ | 値 |
   |---|---|
   | `CALENDAR_ID` | STEP 1-2 で決めたもの（`primary` など） |
   | `SHEET_ID` | STEP 1-1 の【SHEET_ID】 |
   | `LINE_CHANNEL_ACCESS_TOKEN` | STEP 2-5 の【LINE_CHANNEL_ACCESS_TOKEN】 |
   | `HOST_NAME` | 自分の名前（お客様への確認メッセージに差出人として表示されます） |
   | `SERVICE_NAME` | `無料相談（60分）` |
   | `BUSINESS_START` | `10` |
   | `BUSINESS_END` | `18` |
   | `LUNCH_START` | `12`（休憩なしなら入れない） |
   | `LUNCH_END` | `13` |
   | `SLOT_MINUTES` | `60` |
   | `WEEKDAYS` | `1,2,3,4,5`（月〜金。土も受けるなら `1,2,3,4,5,6`） |
   | `DAYS_AHEAD` | `30` |
   | `MIN_LEAD_HOURS` | `24` |
   | `REMINDER_HOUR` | `18` |
   | `ADMIN_LINE_USER_ID` | STEP 2-6 の値（任意） |
   | `MEETING_TOOL` | `meet`（既定）／`zoom`／`none` … 下の「オンライン相談のツールを選ぶ」を参照 |
   | `ZOOM_URL` | `MEETING_TOOL` が `zoom` のときだけ必要。Zoomの固定URL |

### 1-3.（設定の補足）オンライン相談のツールを選ぶ
お客様に案内する参加URLを、`MEETING_TOOL` で切り替えられます。

| 値 | 動き | 必要な準備 |
|---|---|---|
| `meet`（既定・未設定でもこれ） | 予約ごとに **Google Meet のURLを自動発行**して案内する | なし |
| `zoom` | **決まったZoomのURL**を毎回案内する（Zoom側の設定変更は不要） | `ZOOM_URL` に自分のZoom URLを入れる |
| `none` | 参加URLを案内しない（「URLは別途お送りします」と表示） | なし |

**Zoomにする場合の `ZOOM_URL` の取り方**：Zoomアプリの「ミーティング」→ 個人ミーティングID（PMI）の
「招待をコピー」に入っている `https://us06web.zoom.us/j/0000000000` のような**URLの部分だけ**を入れます
（「ミーティングID: 000 000 0000」の行は不要）。

> 💡 固定URLなので、同じ時間帯に2人入れる運用だと同じ部屋に入ってしまいます。
> このキットは1枠1予約なので通常は問題ありませんが、気になる場合は Zoom 側で**待機室をON**にしてください。
> 予約ごとに個別のURLを発行したい場合は Zoom API 連携が必要になるので、担当者に相談してください。
>
> 変更したら `frontend/config.js` の `SERVICE_NOTE`（例:「Google Meet でのオンライン相談です」）も
> 合わせて書き換えてください。予約画面の説明文に出ます。

8. 「保存」してエディタに戻る
9. 上の関数選択で **`selfCheck`** を選んで「▶ 実行」
   - 初回は「承認が必要です」と出る → 自分のGoogleアカウントを選ぶ →「詳細」→「（安全ではないページ）に移動」→
     権限一覧が出たら **「すべて選択」にチェック** →「続行」（2026-09-08 実測。項目ごとのチェック方式に変わっています）
   - 実行ログに「カレンダー: OK」「スプレッドシート: OK」「LINEトークン: 設定あり」と出ればOK
10. 関数選択で **`installReminderTrigger`** を選んで「▶ 実行」（前日リマインドの自動実行を登録）
    - ⚠️ **この関数の実行は必ず自分でやってください。** GASエディタの関数プルダウンはAIが自動操作できないため、
      Claude Code に任せると飛ばされます。実行しないと前日リマインドが一切飛びません
    - 実行後、左の「**マイトリガー**」（時計アイコン）に `sendReminders` のトリガーが1件できていることを確認
11. 右上「**デプロイ**」→「**新しいデプロイ**」→ 種類「**ウェブアプリ**」
    - 説明：`v1`
    - 次のユーザーとして実行：**自分**
    - アクセスできるユーザー：**全員** ← 重要（お客様がログインなしで使うため）
    - 「デプロイ」→ 表示される **ウェブアプリのURL**（`https://script.google.com/macros/s/…/exec`）を **【API_URL】** として控える
12. **【API_URL】の末尾に `?action=ping` を付けてブラウザで開き、`{"ok":true,...}` と表示されることを確認する**
    - 「Authorization needed」と出たら **REVIEW PERMISSIONS** →「詳細」→「（安全ではないページ）に移動」→「すべて選択」→続行
    - この確認を飛ばすと、予約画面から見たときだけ「空き枠を取得できませんでした」になり、原因が分かりにくくなります

> 💡 あとで `Code.gs` を直したときは、「デプロイ」→「デプロイを管理」→ 編集（鉛筆）→ バージョン「新バージョン」→「デプロイ」。URLは変わりません。

## STEP 4｜予約画面を公開する（10分）

`frontend/index.html` と `frontend/config.js` をインターネットに置きます。**この部分は Claude Code に手伝ってもらえます**（`導入手順_ClaudeCodeに読ませる.md` を参照）。

1. `frontend/config.js` を開き、次を記入する
   - `LIFF_ID`：STEP 2-3 の【LIFF_ID】
   - `API_URL`：STEP 3 の【API_URL】
   - `HOST_NAME`：自分の名前
   - `TOPICS`：ご相談内容の選択肢（自由に）
2. Vercel（https://vercel.com）に無料登録して、`frontend` フォルダをアップロードする
   - 画面の「Add New…」→「Project」→ フォルダをドラッグ＆ドロップ、でも可
   - Claude Code に頼めば、コマンドで一発です
   - ログイン画面の選択肢は **Email / GitHub / Google / ChatGPT / SAML SSO / Passkey**（2026-09-08 実測）。GitHubアカウントがあると一番早いです
   - ⚠️ Claude Code にコマンドで頼んだ場合、`vercel login` は
     `Visit https://vercel.com/oauth/device?user_code=XXXX-XXXX` というURLを出して待ちます。
     **このURLをブラウザで開いて承認するのはあなたの操作です**（AIは代行できません）
3. 公開されたURL（`https://xxxx.vercel.app`）を控える → **【FRONT_URL】**

## STEP 5｜LIFFのエンドポイントを本物に差し替える（2分）

1. LINE Developers → LINEログインチャネル → LIFF タブ → 一覧の**右端の「＞」**を押して、作ったLIFFの詳細を開く
2. 「エンドポイントURL」の「**編集**」→ **【FRONT_URL】** に変更して「**更新**」（末尾に `/` は不要）
3. 画面を再読み込みして、エンドポイントURLが差し替わっていることを確認する

### 5-2. チャネルを「公開」にする（お客様に配る前に必須）
LINEログインチャネルは作成直後 **「開発中」** です。この状態では**チャネルの管理権限を持つ人しか予約画面を開けません**。
自分のテストが終わったら、チャネル名の横の「**開発中**」バッジから「**公開**」に切り替えてください。

> 自分でテストするだけなら「開発中」のままでOKです。**他の人に配る前に必ず切り替えてください。**
> 切り替え忘れると、お客様側では予約画面が開かず、原因が非常に分かりにくくなります。

---

## STEP 6｜テストする（5分）

1. 自分のスマホのLINEで、`https://liff.line.me/【LIFF_ID】?src=line` を開く（自分宛にトークで送って、タップすると楽です）
2. 予約画面が開いて、空き時間が表示されることを確認
3. 実際に1件予約する
4. 次の3つを確認
   - Googleカレンダーに予定が入った（Meet のURL付き）
   - スプレッドシートに1行増えた（「経由」が `LINE公式 リッチメニュー`）
   - 自分のLINEに確認メッセージが届いた
5. **エルメの配信が今までどおり動くか**も確認する（テスト配信を1通送る）
6. テスト予約は、カレンダーから削除しておく

3つとも動いたら完成です。
