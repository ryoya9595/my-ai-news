# 事前準備ガイド（DMウォッチシステム）

**本人がブラウザとスマホで行う設定**です。ログインや認証を伴うため、AIには代行できません。
所要時間の目安は **45〜90分**（Metaの画面が一番時間がかかります）。控えるものは最後の「控えメモ」に。

> 💡 Meta（Facebook）の管理画面は、ボタンの名前や配置がよく変わります。このガイドと少し違っていても、**同じ意味の項目を探してください**。迷ったら Claude Code に画面のスクリーンショットを見せて「どれを押せばいい？」と聞くと案内してくれます。

## STEP 1｜Instagram をプロアカウントにする（5分・スマホ）

> ⚠️ 切り替えると **非公開アカウントにできなくなり**、保留中のフォローリクエストは自動承認されます。商用利用不可の音源も使えなくなります。問題ないことを確認してから進めてください。

1. Instagram アプリ → プロフィール → 右上「≡」→「**アカウントの種類とツール**」
2. 「**プロアカウントに切り替える**」
3. カテゴリを選ぶ →「**クリエイター**」を推奨（音源の制限がゆるいため。ビジネスでもDMの取得は同じです）
4. Facebookページとの連携を聞かれたら「**今はしない**」でOK（このキットはFacebookページ不要の方式を使います）

### 🔴 STEP 1-2｜「メッセージへのアクセスを許可」をオンにする（これが無いとDMが1件も取れません）

**プロアカウントに切り替えただけでは、外部のツールからDMを読めません。** Instagram 側でアクセスを
許可するトグルが別にあり、**初期状態はオフ**です。ここがオフだと、あとの手順を全部正しく終えても
API は「エラーなしで会話0件」を返し続けます（2026-09-09 の導入テストで遭遇）。

1. **スマホの Instagram アプリ**を開く（**この設定はPCのブラウザからは変更できません**）
2. プロフィール → 右上「≡」→「**設定とアクティビティ**」
3. 「**メッセージとストーリーズへの返信**」→「**メッセージリクエスト**」
4. 一番上の「**リンク済みのツール**」にある「**メッセージへのアクセスを許可**」を**オン**にする
   （2026-09-09 実測の名称・場所。オフのときはつまみが左でグレー、オンだと右に寄って色が付きます）

> この項目の説明文には「オンにすると、Facebookページ、Meta Business Suite、…**サードパーティアプリ**への
> アクセス許可を持つすべての人が、あなたのInstagramアカウントからメッセージを見たり送信したりできるように
> なります」と書かれています。このキットが使うのは、まさにこの許可です。

> このトグルは Instagram アプリ側の設定なので、Meta for Developers の画面をいくら見ても分かりません。
> 「設定は全部終わったのに `count: 0` のまま」というときは、まずここを疑ってください。

## STEP 2｜Meta for Developers でアプリを作る（30〜50分・PC）

https://developers.facebook.com/ に、**Instagram と同じ人が持っている Facebook アカウント**でログインします。

> 🔴 **Facebookアカウントは必須です。** Instagram と連携させる必要も、投稿する必要もありませんが、
> Meta for Developers（開発者向け管理画面）に入るための入口が Facebook アカウントしかありません。
> 持っていない場合は https://www.facebook.com/ で新規作成してから進めてください。

> 未ログインだと `business.facebook.com/business/loginpage`（タイトル「**Meta for Business（旧Facebook for Business）**」）に飛びます（2026-09-08 実測）。
> 右側の見出しは「**Meta for Developersにログイン**」で、選べるのは
> **「Facebookでログイン」／「新しいアカウントを作成」／「管理対象のMetaアカウントでログイン」** の3つ。
> ふだん使っている Facebook アカウントなら一番上です。

### 2-0. 開発者登録をする（初回だけ・5〜15分）

**Facebook にログインしただけでは、まだアプリを作れません。** 初めて developers.facebook.com を使う場合、
先に「開発者登録」というウィザードが出ます（2026-09-08 実測）。左側に4ステップが並びます。

| ステップ | 画面名 | やること |
|---|---|---|
| 1 | **Register** / 登録 | 利用規約に同意して「次へ」 |
| 2 | **Verify account** / アカウントの確認 | **電話番号にSMSを送って認証** |
| 3 | **Contact info** / 連絡先情報 | メールアドレスの確認 |
| 4 | **About you** / お客様について | 「開発者」などの役割を選ぶ |

> 🔴 **ここが最大の落とし穴です。**
> ステップ2で電話番号を入れようとすると、
> 「**セキュリティ上の理由から、電話番号はまずアカウントセンターで追加する必要があります**」
> と出て**先に進めなくなります**（Facebookアカウントに電話番号を登録していない場合・2026-09-08 実測）。
>
> **対処**：別タブで https://accountscenter.facebook.com/personal_info/contact_points を開き、
> 「**連絡先情報**」→「**新しい連絡先情報を追加**」→ 電話番号を追加してSMS認証を済ませる。
> そのあと開発者登録のタブに戻って、ステップ2をやり直すと通ります。

### 2-1. アプリを作成する（5ステップのウィザード）

1. 右上「**マイアプリ**」→「**アプリを作成**」
2. 🔵 最初に「**Metaのサポートで新しい方法でアプリを作成できます**」という案内モーダルが出ます。
   **右上の「×」で閉じて**、従来のウィザードで進めてください（2026-09-08 実測）。
3. ここからは**5ステップのウィザード**です。左側にステップが表示されます。

| ステップ | 画面名 | 入れる値 |
|---|---|---|
| 1 | **アプリの詳細** | アプリ名：`DM通知`（何でもOK）／連絡先メールアドレス：自分のもの |
| 2 | **ユースケース** | 「**Instagramでメッセージとコンテンツを管理**」を選ぶ（下の🔴参照） |
| 3 | **ビジネス** | 「**現時点ではビジネスポートフォリオをリンクしない**」を選ぶ |
| 4 | **要件** | 読むだけ。そのまま「次へ」 |
| 5 | **概要** | 内容を確認して「**アプリを作成**」 |

> 🔴 **ステップ2のユースケース一覧は、初期表示が「おすすめ（6件）」になっていて、そこに Instagram は出てきません。**
> 一覧の上にある「**すべて（20件）**」に切り替えると出てきます（2026-09-08 実測）。
>
> 選ぶのは「**Instagramでメッセージとコンテンツを管理**」です。
> （説明文：「Instagram APIで投稿の公開、ストーリーズのシェア、コメントへの返信、ダイレクトメッセージへの回答などができます」）
> 「Instagramでビジネスを管理」という選択肢は**今はありません**。
> また、以前の案内にあった「**その他**」→「ビジネス」は、いま選ぶと
> *"This option is going away soon"*（まもなく廃止）と表示されます。**使わないでください。**

> 🔴 **最後に「アプリを作成」を押すと、Facebookの「パスワードをもう一度入力してください」が出ます。**
> ここは本人がパスワードを入力する必要があります（2026-09-08 実測）。

作成に成功すると「アプリダッシュボードへようこそ」というモーダルが出るので、「×」か「詳細を見る」で閉じます。

### 2-2. Instagram の設定を開く

1. 左メニューの「**ユースケース**」を開く
2. 「Instagramでメッセージとコンテンツを管理」の行の右にある「**カスタマイズ**」を押す
3. 左側に出るメニューから「**Instagramログインによる API 設定**」を選ぶ（初期状態で選ばれています）
   - 下に「**Facebookログインによる API 設定**」も並んでいますが、**そちらは使いません**
     （Facebookページが必要になる方式です）

この画面の上部に、次の情報が表示されています。控える必要はありませんが、場所を覚えておいてください。

| 表示 | 内容 |
|---|---|
| **Instagramアプリ名** | `DM通知-IG` のように、アプリ名に `-IG` が付いた名前が自動で入ります |
| **InstagramアプリID** | 数字の羅列（アプリIDとは別物） |
| **Instagram app secret** | 伏せ字。**「表示」を押さないでください**（このキットでは使いません） |

### 2-3. 必要なアクセス許可を追加する

同じ画面の「**1. 必要なメッセージアクセス許可を追加する**」の中に、青いボタン
「**Add all required permissions**」があります。**これを1回押すだけ**で、次の3つがまとめて追加されます。

- `instagram_business_basic`
- `instagram_business_manage_comments`
- `instagram_business_manage_messages`

押すと「必要なアクセス許可をすべて追加しました。」と表示され、見出しの左のアイコンが**緑のチェック**に変わります。

> このキットが実際に使うのは `instagram_business_basic` と `instagram_business_manage_messages` の2つです。
> まとめて追加されるコメント用の権限は、付いていても害はありません。

> 自分のアカウントだけで使う「開発モード」なら、Metaの審査（App Review）は不要です。

### 2-4. 🔴 Instagram アカウントを「Instagramテスター」に登録する（これを飛ばすと必ず失敗します）

**先に、監視したい Instagram アカウントをこのアプリの「Instagramテスター」に登録します。**
これを飛ばして次の 2-5 に進むと、Instagram のログイン後に
**「開発者の役割が不十分です」** というエラーだけが出て止まります（2026-09-08 実測）。

> なぜ必要か：Meta for Developers にログインしている Facebook アカウントと、監視したい Instagram
> アカウントは別物です。アプリ側から「このInstagramアカウントを使ってよい」と明示的に許可しないと、
> トークンを発行できません。

**アプリ側（PC）**

1. 左メニュー「**アプリの役割**」→「**役割**」
2. タブの右端「**その他 ▾**」→「**Instagramテスター**」を選ぶ
   （「テスター」タブとは**別物**です。Facebook側のテスターではなく、Instagram専用の枠です）
3. 右上「**メンバーを追加**」
4. 「このアプリの追加の役割」の中の「**Instagramテスター**」を選ぶ
   - 上に並んでいる 管理者 / 開発者 / テスター / Analyticsユーザー は**選びません**
5. 下に出てくる「**追加したいInstagramアカウントのユーザーネームを入力してください**」に
   `ryosan5454` のような **@なしのユーザーネーム**を入れる → 候補が出たらクリックして確定 → 「**追加**」
6. 一覧に追加され、ステータスが「**承認待ち**」になればOK

**Instagram 側（招待の承認）**

7. 監視したいアカウントで Instagram にログインした状態で
   https://www.instagram.com/accounts/manage_access/ を開く
   （スマホアプリなら：プロフィール →「≡」→ 設定 → 「**アプリとウェブサイト**」）
8. 右端のタブ「**テスターへのご招待**」を開く
9. アプリ名（`DM通知-IG` のように `-IG` が付いた名前）が表示されるので「**承認する**」
   > 承認は Meta のプラットフォーム利用規約・開発者ポリシーへの同意を伴います。内容を確認して本人が押してください
10. アプリ側の一覧に戻ると、ステータスが「承認待ち」から変わります

### 2-5. アクセストークンを発行する

2-3 の画面（ユースケース → カスタマイズ → Instagramログインによる API 設定）に戻り、
下にスクロールすると「**2. アクセストークンを生成する**」があります。

1. 「**アカウントを追加**」を押す
2. 「**Instagramアカウントを追加**」というモーダルが出ます。内容を確認して「**次へ**」
   > 🔴 このモーダルに、大事な条件が2つ書かれています（2026-09-08 実測）。
   > - **「追加できるのは Instagram プロアカウントのみです」**
   > - **「トークンは、公開Instagramアカウント用にのみ生成できます」**
   >   → **非公開（鍵つき）アカウントではトークンを発行できません。** STEP 1 でプロアカウントに
   >     切り替えていれば非公開にはできないので、通常は問題ありません。
3. **別ウィンドウで Instagram のログイン画面**が開きます。STEP 1 のアカウントでログインし、
   求められた権限を「**許可**」する
4. 表示されたトークン（長い文字列）を **【IG_ACCESS_TOKEN】** として控える
   - **このメモには書かず、パスワード管理ツール等に保存**してください
   - 有効期限は **約60日**。更新方法はこのガイドの最後にあります

> 🔵 その下にある「**3. Webhooksを設定する**」は、**このキットでは設定不要**です。
> このキットは決まった時刻にこちらから取りに行く方式（ポーリング）なので、
> Meta からリアルタイムで受け取る Webhook は使いません。コールバックURLは空のままでOKです。

### 2-6. 動作確認（任意・おすすめ）
Meta の「**Graph API エクスプローラ**」（ツール → Graph API Explorer）で、上のトークンを使って `me?fields=id,username` を実行し、自分のユーザー名が返ってくればOK。
「メッセージの取得も確認したい」場合は `me/conversations?platform=instagram` を実行して、エラーにならなければOKです。

## STEP 3｜通知を受け取る LINE の準備（15分・PC）

### 3-1. 通知専用の LINE公式アカウントを作る（推奨）
既存の公式アカウント（エルメと連携中のもの）でも通知は送れますが、**通知専用のアカウントを1つ新しく作る**ことをおすすめします。理由：
- エルメ側のトークンやWebhookに**一切触らずに済む**（事故ゼロ）
- 無料枠（月200通）が**別枠**になる
- 通知が他の配信と混ざらない

1. https://manager.line.biz/ →「**LINE公式アカウントを作成**」→ アカウント名「DM通知」など → 業種は任意 → 作成（無料）
2. 作ったアカウントの「設定」→「**Messaging API**」→「**Messaging APIを利用する**」
   - プロバイダーは「新規作成」でOK（名前は自分の名前など）
   - Webhook URL は**空欄のまま**でOK（受信はしないので）
3. https://developers.line.biz/console/ を開くと、今作ったプロバイダーと Messaging API チャネルが見えます

### 3-2. チャネルアクセストークンを発行
1. LINE Developers → そのチャネル →「**Messaging API設定**」タブ
2. 一番下「**チャネルアクセストークン（長期）**」→「**発行**」
3. 表示されたトークンを **【LINE_CHANNEL_ACCESS_TOKEN】** として控える（パスワード管理ツールへ）

> 既存の公式アカウント（エルメ連携中）を使う場合は、**「再発行」は絶対に押さない**でください。エルメが止まる可能性があります。トークンが見えない状態なら担当者に相談を。

### 3-3. 通知を受け取る人の LINE userId
1. 同じチャネルの「**チャネル基本設定**」タブ → 一番下「**あなたのユーザーID**」（`U` から始まる33文字）→ **【LINE_TO_USER_ID】**
2. **通知専用アカウントをスマホのLINEで友だち追加**しておく（友だちでないと届きません）。「Messaging API設定」タブの QRコードを読み取ればOK
3. 通知を受け取る人が別にいる場合は、その人にも友だち追加してもらい、userId を確認する（複数人に送る場合は、1通が人数分カウントされます）

## STEP 4｜Claude のクラウド環境にトークンを登録する（10分・PC）

Claude が動く環境に、トークンを**安全に**預けます。ここに登録したトークンは、Claude 本体にも、実行されるコマンドにも見えません（通信の途中で自動的に付与される仕組み）。

> この機能は **Pro / Max プラン**で使えます。Team プランの場合は STEP 4-B へ。
> 環境の設定画面は「設定」メニューの中にはありません。**ルーティンの作成画面から開きます**（4-A の手順1〜4）。

### 4-A. API認証情報に登録（Pro / Max）

> 画面はすべて日本語です。英語のドキュメントにある `API credentials` は「**API認証情報**」、
> `Environment variables` は「**環境変数**」、`Network access` は「**ネットワークアクセス**」です。

**環境の設定画面の開き方**（2026-09-09 実測。ここが分かりにくい）

1. https://claude.ai/code を開く
2. 左メニュー「**ルーティン**」→ 右上「**＋ 新しいルーティン**」
   （設定メニューの中に環境の項目はありません。**環境はルーティン作成画面から開きます**）
3. 「指示」欄の**右下にある「☁ Default」チップ**をクリック → 環境の一覧が出る
4. 🔴 **一覧の行にマウスを乗せると、右端に歯車アイコンが出ます。これが「編集」です**
   （ラベルが無いので気づきにくい）

**専用の環境を作る（推奨）**

5. 一覧の「**＋ クラウド環境を追加**」を選ぶ
6. 次を入れて「**環境を追加**」

   | 項目 | 値 |
   |---|---|
   | 名前 | `IG DM通知` |
   | ネットワークアクセス | `Trusted`（既定のまま） |
   | 環境変数 | 下の枠の2行 |
   | セットアップスクリプト | 空のまま |

   ```
   LINE_TO_USER_ID=【LINE_TO_USER_ID】
   IG_WINDOW_HOURS=4.5
   ```
   - `IG_WINDOW_HOURS` は「**最低これだけは遡る**」という下限です。前回チェックした時刻がそれより前なら、
     そこまで自動的に遡るので、夜間など実行が空く時間帯のDMも取りこぼしません
   - 長期間止めていた場合の上限は 72 時間です（変えたい場合は `IG_MAX_LOOKBACK_HOURS` を追加）
   - 🔴 **「クラウド環境を追加」の画面には API認証情報の欄がありません。** 作ったあとに
     もう一度チップから開いて、**歯車（編集）**を押すと現れます

**トークンを登録する**

7. 作った `IG DM通知` の**歯車**を押して編集画面を開き、下の方の「**API認証情報**」→「**＋ 認証情報を追加**」
8. 次の2つを1つずつ登録する

   | 名前 | 認証情報タイプ | 許可ウェブサイト | カスタムヘッダーの「値」 |
   |---|---|---|---|
   | `Instagram` | `Bearer` | `graph.instagram.com` | 【IG_ACCESS_TOKEN】 |
   | `LINE` | `Bearer` | `api.line.me` | 【LINE_CHANNEL_ACCESS_TOKEN】 |

   - 認証情報タイプで `Bearer` を選ぶと、**カスタムヘッダーの行（名前 `Authorization` / プレフィックス `Bearer`）が
     最初から入っています**。自分で足す必要はありません。入れるのは右端の「**値**」だけです
   - 「追加先」は開いた環境が自動で入ります（`Environment: IG DM通知`）
   - 🔴 **値は保存後どこにも表示されません**（画面にも「値は保存後に表示できず、環境変数やファイルとして
     セッションに渡されることもありません」と書かれています）。書き換えたいときは**削除して追加し直す**
   - 「**認証情報は追加または削除すると同時に保存されます**」＝この2つは追加した時点で確定します

9. 最後に編集画面の「**変更を保存**」を押す（環境変数やネットワークアクセスの変更を確定するため）

### 4-B. Team プランの場合（API認証情報が使えない）
1. 環境の「**ネットワークアクセス**」を **Custom** にして、許可ドメインに次を追加（「既定のリストも含める」にチェック）
   ```
   graph.instagram.com
   api.line.me
   ```
2. 「**環境変数**」に次を追加
   ```
   IG_ACCESS_TOKEN=【IG_ACCESS_TOKEN】
   LINE_CHANNEL_ACCESS_TOKEN=【LINE_CHANNEL_ACCESS_TOKEN】
   LINE_TO_USER_ID=【LINE_TO_USER_ID】
   IG_WINDOW_HOURS=4.5
   ```
   > この方式では、環境を使う人にトークンが見えます。自分だけが使う環境なら問題ありません。

## STEP 5｜リポジトリにキットを置く（Claude Code に手伝ってもらう）

このキットを GitHub の**非公開リポジトリ**に置きます。手順は `導入手順_ClaudeCodeに読ませる.md` にあり、Claude Code がやってくれます。
準備として、GitHub アカウント（https://github.com）を持っていて、Claude Code から GitHub に接続済みであることを確認してください（claude.ai/code の初回設定で行うもの）。

> 🔴 **非公開リポジトリを新しく作った場合、そのままではルーティンのリポジトリ一覧に出てきません**（2026-09-09 実測）。
> Claude の GitHub アプリが「選んだリポジトリだけ」に許可されているためです（公開リポジトリは自動で読み取り可）。
>
> **対処**：https://github.com/settings/installations →「**Claude**」の「**Configure**」→
> （本人確認を求められたら認証）→「Repository access」の「**Only select repositories**」で
> 「**Select repositories**」から新しいリポジトリを選ぶ →「**Save**」。
> そのあと claude.ai に戻り「**GitHubの連携を完了する**」を押すと、一覧に出るようになります。
> 「All repositories」にしておけば、以後この作業は不要です。

## STEP 6｜ルーティンを作る（10分・PC）

1. https://claude.ai/code → 左メニューの「**ルーティン**」→ 右上の「**＋ 新しいルーティン**」
   （画面上の表記は「新規作成」ではなく「新しいルーティン」です・2026-09-08 実測）
2. 設定

   | 画面の項目名 | 入れる値 |
   |---|---|
   | **名前**（必須） | `Instagram DMチェック` |
   | **指示** | `routine-prompt.md` の `---` の間を**そのまま貼り付け**（この欄が「プロンプト」にあたります） |
   | 「指示」欄の下の **リポジトリを選択** | STEP 5 で置いたリポジトリ（見つからないときは STEP 5 の🔴を実施） |
   | 「指示」欄の下の **雲アイコン＋Default** | STEP 4 で設定した環境を選ぶ（**環境の選択欄はここにあります**。独立した「環境」項目はありません） |
   | **トリガーを選択** | 「**スケジュール**」を選ぶ（他に GitHubイベント / API があります） |
   | スケジュールの中身 | 出てきたチップをクリック →「**カスタム**」→「**cron式**」に `0 1,5,8,10 * * *` を入れる（**UTC表記**。日本時間の 10:00 / 14:00 / 17:00 / 19:00） |
   | 下部タブ **コネクター** | 🔴 **既定で6個ほど付いています。「×」で全部外してください**（実測では Adobe for creativity / Canva / Gmail / Google Calendar / Google Drive / visualize / Claude_Code_Remote）。このシステムには不要で、付けたままだと Gmail や Drive への書き込みが確認なしで許可されます |
   | 下部タブ **動作 / 通知** | 触らなくてOK |

   > 💡「毎日／平日／毎週」などのプリセットもあります。**プリセットの時刻は JST 表記、cron式は UTC** です
   > （17:00 JST を選んでから「カスタム」に切り替えると `0 8 * * *` になることを確認済み）。
   > また「サーバー負荷を分散するため、実行は数分ずつずらされます」と注記があり、**きっかり10:00には届きません**。

3. 右下の「**作成**」
   > 🔴 **作成した直後に、外したはずのコネクターが復活していることがあります**（2026-09-09 実測）。
   > 作成後の画面の「実行環境」欄を確認し、コネクターが並んでいたら
   > 「**編集**」→ コネクターを「×」で全部外す →「**保存**」をもう一度行ってください。
   > 保存後に「実行環境」がリポジトリ名と環境名だけになっていれば成功です。
4. 「**今すぐ実行**」で1回動かす
5. 数分後、LINE に通知が来ればOK（新着DMがなければ何も来ません。その場合は、テスト用に別のアカウントから自分にDMを送ってから、もう一度「今すぐ実行」）

## トークンの更新（約60日ごと）

Instagram のトークンは約60日で切れます。切れると LINE に「⚠️ Instagram DMチェックが失敗しました」と届きます。

**期限内に更新する場合**（発行から24時間以上経っていればOK）：
自分のPCのターミナルで
```
IG_ACCESS_TOKEN="今のトークン" python3 dm-watch/scripts/refresh_token.py
```
> ⚠️ このコマンドは**新しいトークンを画面に表示します**。**Claude Code にこのコマンドを実行させないでください**
> （AIの画面にトークンが出てしまいます）。必ず自分でターミナルに打ち、終わったらそのターミナルを閉じてください。
→ 新しいトークンが表示される → STEP 4 の `Instagram` の credential を削除して、新しい値で登録し直す（編集はできないので、削除→追加）

**期限が切れてしまった場合**：STEP 2-5 でもう一度「アカウントを追加」してトークンを発行し直し→ STEP 4 で登録し直す

> 💡 カレンダーに「50日後」でリマインドを入れておくと忘れません。
